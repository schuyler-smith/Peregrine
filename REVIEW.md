# REVIEW (Peregrine) — one review before showing it

**How it was checked:** I ran the full flow in a real browser (Chrome, headless) against sample data: life list import, place search, adding a stop by clicking the map, a per-stop date, reordering, dragging a pin, the This stop and Whole trip tabs, filters, Save → reload → My trips, and Export → New → Import. I also ran it in real mode with no key to check the first-run and error paths, and tested the server's endpoints directly with curl. Then I read the code with fresh eyes.

## Fixes (all done ✅)

| # | Found | Fix |
|---|-------|-----|
| 1 | Life list import dropped subspecies-group entries such as "Dark-eyed Junco (Slate-colored)" because their scientific name contains a "/". Junco would have shown as a false lifer. | Only skip "/" when it's in the genus/species part (true slashes like "Black/Mallard"). Subspecies groups now count toward their species. Re-tested: Junco is no longer flagged. ✅ |
| 2 | Other websites open in your browser could, in principle, send requests to the local server (save trips, change the key, use your key through the proxy). | The server only answers requests addressed to `localhost`/`127.0.0.1`, and changes need a custom app header that other sites can't send. Tested: requests without the header or with a foreign Host get 403. ✅ |
| 3 | The eBird proxy accepted `..` in paths. | Paths containing `..` are rejected, and only the three eBird endpoints the app uses are allowed. ✅ |
| 4 | While other stops were loading, the This stop / Whole trip list was rebuilt on every request, which can make the list jump while you scroll. | Lists only redraw when what they show actually changes. ✅ |

| 6 | The lifer badge on a pin covered the stop number. | Moved the badge to the upper right. ✅ |
| 7 | With no key, a stop just showed an error. | The error now has **Open Settings** and **Try again** links, and saving a key retries failed stops automatically. ✅ |

## Known limits (by design, noted in README)
- Likelihood is "share of days reported in the county", not Merlin's model, which isn't public. Busy counties read higher.
- A first load at ±15 days is about 155 eBird requests per stop. They're cached afterwards.
- A Feb 29 trip date uses Mar 1 in non-leap years.

## Still to confirm on the first real run
The sandbox I built in can't reach eBird, so live eBird answers were simulated with sample data in the same format eBird uses. The first time you add a stop with your real key, check that a list appears. If anything errors, the message on screen will say what eBird replied.
